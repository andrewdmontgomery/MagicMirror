# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

A Docker-based configuration setup for [MagicMirror²](https://docs.magicmirror.builders/) (a Raspberry Pi smart-mirror platform). There is no local Node install and no build step — the actual MagicMirror runtime lives inside the `karsten13/magicmirror` Docker image. This repo only contains what's mounted into that container: `docker-compose.yml`, the mirror's config, and four custom first-party modules (HourlyStrip, WindCompass, WeatherMap, WeatherWatcher).

## Commands

- Start the mirror: `docker compose up -d`
- **Apply any change to `mounts/config/config.js` or a module**: `docker compose restart magicmirror` — MagicMirror does not hot-reload config or module code, a restart is required after every edit.
- **After changing `docker-compose.yml` itself (e.g. adding a volume mount)**: `docker compose down && docker compose up -d` — `restart` reuses the existing container and silently ignores new mounts, which leaves the new mountpoint as an empty dir inside the container (module JS then 404s and the module renders nothing).
- Check for startup/runtime errors: `docker compose logs --tail=50 magicmirror`
- Stop: `docker compose down`
- View the mirror: `http://localhost:8080` (runs in server-only mode — no Electron/kiosk display needed on the host; any browser works)

There is no build step. Lint with `npm run lint` (after `npm ci`; ESLint 9 + neostandard over first-party code only — `vendor/`, test fixtures, and generated `basepath.js` are exempt; config in `eslint.config.mjs`). Tests are unit-only via `node --test`: `npm test` runs the HourlyStrip + WeatherMap + WeatherWatcher suites (`*/tests/unit/*.test.js`, pure logic — no DOM, no map, no timers). Keep lint and tests green before every commit; `test` / `lint` / `actionlint` workflows also gate every PR (`.github/workflows/`, `pull_request` triggers only). Local Node and CI both use Node 22. WindCompass has no suite.

## Architecture

`docker-compose.yml` bind-mounts `mounts/config` (→ `/opt/magic_mirror/config` — holds `config.js`) plus each first-party module individually (`mounts/modules/<Name>` → `/opt/magic_mirror/modules/<Name>` for WindCompass, WeatherWatcher, HourlyStrip, WeatherMap) — individual mounts, rather than the whole `modules/` dir, so the container's own bundled default modules stay untouched. `basepath.js` and `custom.css` in the config directory are generated by the container's entrypoint script at runtime and are gitignored; don't hand-edit or expect them to persist meaningfully.

### Module layout (`config.js`)

All location modules share one hardcoded lat/lon (Inver Grove Heights, MN) with purely descriptive headers rather than repeating the location — `appendLocationNameToHeader: false` is set on both `weather` instances for this reason:
- `clock` (top_left)
- `weather` × 2 (top_right) — one `type: "current"`, one `type: "forecast"`, both using the `openmeteo` provider
- `MMM-HourlyStrip` (bottom_bar) — 24 h Open-Meteo hourly strip; its `WEATHER_UPDATED` hourly feed drives the Watcher below
- `MMM-WindCompass` (bottom_right) — the custom compass module
- `MMM-WeatherMap` (bottom_left) — MapLibre rain/wind/AQI map, view-controlled via `WEATHERMAP_SET_VIEW`
- `MMM-WeatherWatcher` (no position) — picks the map's default view from the strip's precip forecast plus the map's home AQI

**Weather provider**: deliberately `openmeteo`, not `openweathermap`. OpenWeatherMap's provider in the weather module calls `/data/3.0/onecall`, which requires an active paid subscription (card on file) even at zero usage — Open-Meteo is free/keyless and covers the same current+forecast+UV+wind data used here.

### MMM-WindCompass

A custom module, split the standard MagicMirror way:
- `node_helper.js` — server-side; fetches current wind speed/gusts/direction from Open-Meteo's forecast API on `updateInterval`. Fetching happens here (not in the front-end file) because it needs to run in Node, not the browser.
- `MMM-WindCompass.js` — front-end; receives data via `GET_WIND_DATA` / `WIND_DATA_RESULT` socket notifications, renders a metrics list (wind/gusts/direction) plus a hand-built SVG compass dial (`buildCompassSvg`).
- `MMM-WindCompass.css`

Two things worth knowing before touching this module:
- **The compass SVG is fully parametric.** Every dimension (ring radius, disc radius, tick length, arrowhead/tail size, canvas size) derives from a handful of constants at the top of `buildCompassSvg`. Resizing the compass means changing `ringRadius`/`discRadius`/`tickLength` there, not hand-adjusting coordinates throughout the function.
- **`getHeader()` returns HTML, not plain text** — it supports an icon (`showHeaderIcon`), header text (the standard MagicMirror `header:` field), and an optional `locationName` appended after it, in any combination, always falling back to "Wind" so the header is never blank. This differs from the built-in `weather` module, whose `getHeader()` only ever returns a plain string — MagicMirror's core framework supports HTML in headers for any module (it just does `header.innerHTML = getHeader()`), the built-in weather module simply doesn't use that capability.

## Git

`main` is the default branch. `weather-module` also exists (it was the original working branch before `main` was created from its tip).

Never edit on `main`: create the feature branch first and verify with `git branch --show-current` **before** the first file change — including scratch or prototype edits. `main` only moves via merges/PRs.
